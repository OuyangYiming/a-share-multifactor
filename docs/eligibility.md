# 历史样本资格过滤器

`src/eligibility.py` 实现 ST、停牌和上市不足 60 个交易日的逐条筛选. 它只处理传入的历史资料，不下载或推断缺失状态，不建立全 A 股证券池. 过滤器可运行不等于历史资料已经齐备，也不等于阶段 1 已经完成.

## 输入与时点约束

```python
from src.eligibility import classify_eligibility, summarize_eligibility

classified = classify_eligibility(records, trading_calendar)
annual = summarize_eligibility(classified)
```

`records` 为 DataFrame，每条记录代表一只股票的一个交易日. `(date, code)` 必须唯一，输入顺序、索引及其他字段保留不变.

| 必需列 | 合同 |
|---|---|
| `date` | 当日交易日期，不得缺失，必须存在于传入日历. |
| `code` | 已统一格式的非空证券代码字符串. |
| `listing_date` | 经核验的上市日期，允许缺失；不得晚于当日日期. 首条价格观测不能代替上市日期. |
| `is_st` | 适用于当日的历史 ST 标记，只接受布尔值、数值 0/1 或缺失. |
| `is_suspended` | 适用于当日的历史停牌标记，取值规则同上. 不由零成交量推断. |
| `st_asof` | 该行历史 ST 状态最早已知的日期，允许缺失，但不得晚于 `date`. |
| `suspension_asof` | 该行历史停牌状态最早已知的日期，规则同上. |

所有日期须为无时区、无日内时间的日期. `is_st` 和 `is_suspended` 中的字符串 `"False"`、`"0"` 等会被拒绝，调用方应按明确字段定义解析. 缺少任一必需列会报错，不自动把输入当作当日已知.

`asof` 表示信息何时已知，不是本次下载或写文件的日期. 调用方必须保证标记在该行日期有效，并有历史来源支持. 不能把当前 ST 名单复制到历史日期，再填写过去的 `asof` 来通过校验. 模块只能校验日期关系，无法认证输入声明是否真实.

只要任一非空 `st_asof` 或 `suspension_asof` 晚于 `date`，整批报错；对应标记缺失时也不例外. 标记非缺失但 `asof` 缺失时，该项仍为未知. 同日信息按当日收盘时已知处理；实际交易仍须在后续回测中执行最早下一交易日成交的约束.

## 交易日历与上市年龄

`trading_calendar` 必须是非空、递增、无重复、无缺失的 `pd.DatetimeIndex`，只含交易日，日期无时区且无日内时间. 调用方须通过日历来源核验首尾范围内交易日的完整性. 本模块校验结构，无法仅凭一列日期判断上游是否漏掉交易日.

上市交易日年龄定义为日历中满足 `listing_date <= session <= date` 的交易日数. 上市当日若为交易日，年龄为 1；第 59 个交易日被排除，第 60 个交易日通过年龄条件. 周末和休市日不计入；股票因停牌缺少行情行时，交易所交易日仍计入上市年龄. 不能把窗口中的前 60 条行情当作上市前 60 个交易日.

上市日期缺失或早于所提供日历的首日时，精确年龄为 `pd.NA`，年龄条件为未知. 这是当前实现的保守约定：即使较短日历可能足以证明某股票已上市超过 60 日，本模块也不推断年龄下界. 应提供覆盖上市日期的完整日历. 上市日期位于日历范围内但为休市日时，从其后首个交易日开始计数.

## 输出与互斥计数

输出保留来源标记的缺失状态，并添加：

| 输出列 | 含义 |
|---|---|
| `listing_trading_days` | 精确上市交易日数，类型为可空整数 `Int64`. |
| `st_unknown` | ST 标记或其 `asof` 缺失. |
| `suspension_unknown` | 停牌标记或其 `asof` 缺失. |
| `listing_age_unknown` | 上市年龄不能在合同规定下计算. |
| `unknown_fields` | 用逗号列出未知项：`st`、`suspension`、`listing_age`. 已由其他条件排除的记录也保留此信息. |
| `eligibility_status` | 下表中的唯一分类. |
| `eligible` | 合格为 `True`，明确排除为 `False`，不能确定为 `pd.NA`，类型为可空布尔值. |

按以下顺序匹配，匹配成功后不重复计入后续类别：

| 顺序 | 分类 | 判定条件 |
|---:|---|---|
| 1 | `excluded_st` | 已核验时点的 ST 标记为真. |
| 2 | `excluded_suspended` | 未被上一条排除，且已核验时点的停牌标记为真. |
| 3 | `excluded_new_stock` | 未被前两条排除，且已知上市年龄小于 60 个交易日. |
| 4 | `unknown` | 未被任何已知条件排除，但至少一项必要信息未知. |
| 5 | `eligible` | 三项信息均已知，且均通过. |

例如，ST 状态未知、但已知仅上市 20 个交易日的记录归入 `excluded_new_stock`，同时保留 `st_unknown=True`. 已上市满 60 日而历史 ST/停牌资料缺失的记录归入 `unknown`，不能进入合格样本. `unknown` 不是证明有风险，也不是证明可以纳入.

`summarize_eligibility()` 只输出输入中实际存在的年份. `input_rows` 与五类结果的计数单位均为股票-日期记录；五类之和严格等于 `input_rows`. `input_stocks` 和 `eligible_stocks` 另行按证券代码去重，不等于记录数. 同一只股票一年中可能出现在多个分类，因此不能把各类记录数解释成互斥的股票只数. 没有出现的市场记录、停牌日或证券不会被凭空补入.

五股试点的年度表应称为试点统计，例如 `pilot_sample_summary.csv`，不能作为全 A 股最终 `sample_summary.csv` 的完成证据. 缺失的历史状态仍需补齐，并与历史全市场证券池、退市证券、行业、估值及基准资料一起验收.

## 实现与验证

`validate_calendar()` 检查日历结构. `classify_eligibility()` 检查键和日期，保留可空状态，再利用交易日历中左右插入位置的差计算年龄，最后按互斥优先级赋予分类. 它不从后一行向前填补任何信息，因此新增或修改未来记录不会改变此前记录的分类.

`summarize_eligibility()` 逐年统计分类并检查计数守恒. 没有任何类别被填作“筛选成功”：未知状态始终单独保留.

```bash
python -m pytest tests/test_eligibility.py -q
```

测试全部使用明确标注的构造记录与构造交易日历，不是行情数据. 测试覆盖第 59/60 交易日、休市日、不完整历史日历、状态与时点缺失、未来时点拒绝、互斥优先级、统计守恒和未来记录变化对过去结果的影响. 测试通过只证明实现遵守此数据合同，不证明输入市场资料完整或真实，也不代表完整回测的未来函数检查已完成.
