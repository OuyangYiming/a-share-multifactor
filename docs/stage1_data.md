# 阶段 1：五只股票的数据管道试点

本模块完成五只预先指定股票的历史行情下载、两种复权口径对齐、缓存与字段覆盖审计. 尚未完成全 A 股数据管道，也未完成 ST、停牌、新股剔除及行情软件抽查.

## 运行

安装项目锁定依赖后，在项目根目录运行：

```bash
python -m src.data
python -m src.data --offline
python -m pytest tests/test_data.py -q
```

首次命令串行下载，不并发请求. HTTP 连接/读取超时设为 15 秒，调用结束后恢复 SDK 原设置；这不是整批任务的 15 秒总时限. 发生异常时停止，成功保存的快照可供下次继续使用. `--offline` 要求本地快照齐全，缺少文件时明确失败.

## 数据合同

固定样本为 `sh600000`、`sz000001`、`sh600519`、`sz000002`、`sz300750`，请求区间为 2015-01-01 至 2025-12-31. 每只股票分别调用 AKShare `stock_zh_a_hist_tx` 的 `adjust=''` 与 `adjust='hfq'`. 股票为预先指定的接口试点，不是随机抽样，也不是依据历史证券池选出的研究样本.

| 处理后字段 | 含义与口径 |
|---|---|
| `date, code` | 交易日期和证券代码，共同构成唯一键. 代码来自请求参数，并非上游返回的独立身份校验. |
| `open, close, high, low` | 不复权开盘、收盘、最高与最低价，单位为元. |
| `hfq_open, hfq_close, hfq_high, hfq_low` | 请求后复权得到的对应价格，只作连续价格序列分析，不作实际成交报价. |
| `volume` | 不复权接口表的成交量；当前锁定 SDK 已统一为股，不再次乘 100. |
| `amount` | 不复权接口表的成交额；当前锁定 SDK 已统一为元，不再次乘 10000. |
| `turnover` | 不复权接口表的换手率，以小数表示，例如 0.01 表示 1%. |

单位依据为锁定 AKShare 源码的转换逻辑，尚未与独立行情软件核对. 原始缓存分别保留两次调用返回的全部 SDK 列；合并表的成交量、成交额与换手率选用不复权表，不对这些字段进行价格复权. 复权方向来自明确的请求参数，本模块没有独立计算或核验复权因子.

`data/stage1/raw/` 保存 SDK DataFrame 序列化 CSV 及其 JSON 来源记录，而不是 HTTP 原始响应体. `data/stage1/processed/pilot_daily.csv` 保存按日期、代码排序的合并表. 行情数据均留在被 Git 排除的 `data/` 目录.

## 校验与缓存

缺少必需列、空表、日期缺失、区间越界、重复日期、OHLC 缺失/非正/非有限值或不满足最低价不高于开收盘价、最高价不低于开收盘价，均报错停止. 成交量、成交额和换手率允许缺失并统计缺失数，拒绝负数与无穷值，不填成零. 不复权与后复权的日期、代码集合必须完全一致，不能用内连接静默丢弃不匹配记录.

本模块不执行 `drop_duplicates`，但上游 SDK 本身会合并窗口并去除完全相同的行. 因此结果中的重复键为零只说明收到并保存的 SDK 输出通过校验，不能证明原始上游响应从未存在重复或遗漏.

每份缓存的 SHA256 与请求参数、来源、SDK 版本和下载时间一起保存. `results/stage1_provenance.json` 保存可提交的参考清单. CSV 与本地来源记录缺少任意一件时拒绝读取；缓存内容变化、参数变化或重新下载与公共参考校验值不同时也停止，不自动刷新参考值. 后续上游修订应保留原始快照并另行审查. 仅保留公共校验值不能恢复丢失的行情；跨机器重新下载仍依赖上游可达且返回相同数据.

## 实际结果与证据

本次五股共取得 12,366 条配对后的股票-日期记录，两种价格口径的日期集合均对齐；无重复键和缺失 OHLC. 这不表示交易日覆盖完整，也不证明价格与外部行情一致. 总量及校验结论见 `results/stage1_audit.json`，逐股结果如下，来源为 `results/tables/stage1_stock_summary.csv`.

| 证券代码 | SDK 返回记录数 | 首条观测日期 |
|---|---:|---|
| sh.600000 | 2642 | 2015-01-05 |
| sz.000001 | 2674 | 2015-01-05 |
| sh.600519 | 2674 | 2015-01-05 |
| sz.000002 | 2539 | 2015-01-05 |
| sz.300750 | 1837 | 2018-06-11 |

首条观测日期不是经过核验的上市日期. 不同股票和年份的记录数量差异，需要交易日历、上市资料和停牌记录才能解释，不能直接归因于停牌.

| 输出文件 | 内容 |
|---|---|
| `stage1_stock_year_coverage.csv` | 固定五股与全部请求年份的组合，记录各股各年行数与首末观测日；没有观测的组合保留零行数. |
| `stage1_year_coverage.csv` | 每年实际有观测的试点股票数与记录数，不是全市场股票数或合格样本数. |
| `stage1_field_coverage.csv` | 已取得字段的实际非空/缺失数量，以及本接口试点尚未取得的研究字段. |
| `stage1_activity_missing.csv` | 按股票、年份统计成交量、成交额和换手率缺失数量. |
| `stage1_stock_summary.csv` | 各股观测区间、记录数及零成交量行数；零成交量不等同于已核验停牌. |

以上 CSV 均位于 `results/tables/`. 本模块不输出全 A 股 `sample_summary.csv`，不把尚未执行的筛选规则写成“剔除 0 只”.

## 尚未完成的条件

本行情模块本身不取得历史证券池、ST、停牌、上市日期、日历、行业与估值. 后续 `reference_data.py` 已补齐本试点的上市日期、日历和两项基准，`sample_audit.py` 据此计算上市交易日数并执行已知新股排除，见 `docs/reference_data.md` 与 `results/stage1_progress.json`. 全市场历史证券池、历史 ST/停牌、时点行业、市值及 PE/PB 仍未完成验收. 不用窗口内前 60 行代替上市年龄，不把缺少的 ST/停牌标记填成 False.

五只股票均为指定样本，尚未做任务书要求的随机五股独立行情软件比对；也未验证退市股、北交所覆盖和原始行情日期完整性. 当前还没有信号或交易逻辑，不能称为无未来函数回测验收通过. 正式样本与筛选数量须在补齐这些资料后另行生成.

## 代码讲解

`validate_vendor_frame()` 把 SDK 的表转换成明确的数据合同. 它发现错误后终止，让错误无法混入后续合并表；允许的活动字段缺失保持原样并进入审计.

`load_snapshot()` 先检查本地文件和来源记录是否配对、请求是否相同、内容校验值是否一致，再返回数据. 没有缓存才下载；公共参考清单将重新下载结果与本次输入绑定.

`align_adjustments()` 先比较两张表的日期代码集合，再一对一合并. `code` 相同但 `date` 缺一日也会失败，避免价格序列错位.

`build_coverage()` 先构建全部年份与固定五股的组合，再把实际行数填入. 零只表示该组合没有收到记录，不表示未上市、停牌或筛选删除.

`run_pilot()` 按固定顺序调用以上步骤，最后由 `write_audit()` 输出可追溯的统计表. 本人验收应能解释：两份价格为什么分开保存、为什么合并前要求键集合相同、为什么缺失 ST 信息不能当作“非 ST”.
